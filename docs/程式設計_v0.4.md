## 1. 不變的原則

- 一個案子一個資料夾；每步讀檔寫檔；編號即順序
- CSV 為主（幾何用 WKT 欄位）；程式用 `dict` 不用 dataclass
- 尺寸是幾何、線段只是拓樸；座標只來自數字與量測
- 不確定往上傳不往下傳；**矛盾是產出，不是障礙**
- 一開始不上資料庫、不做網頁校對（Excel 先頂）、不追求全自動

**一條例外**：v0.3 說「不要大 main()」——中樞迴圈是唯一的例外，它需要一個 orchestrator（§5）。其餘各步仍可單獨執行。

### 1.1 `io.final(row)` ★ v0.4.1 新增

```python
def final(row: dict) -> float | None:
    """人工修正優先於 AI 判讀。下游一律用這個，不要直接讀 value 欄。"""
    return num(row.get("verified_value")) or num(row.get("value"))
```

**語意**：`verified_value`（人在校對介面確認的）優先；沒有才用 `value`（系統採信的）。
兩者皆空 → 回 `None`，代表這個值未定，**不准往下游傳**。

### 1.2 三源 ＝ 三個「機制上獨立」的來源 ★ v0.4.1 新增

| 欄位 | 來源 | 靠什麼判斷 | 會被什麼騙 |
|---|---|---|---|
| `src_paddle` | PaddleOCR-VL | 字形比對 | 糊掉的字形 |
| `src_vlm` | VLM | 語意理解、上下文 | 糊掉的字形 ＋ **幻覺** |
| `src_geom` | 幾何比例 | 端點距離 × 比例尺，**完全不看文字** | 透視/掃描變形 |

**第三源是關鍵。** 前兩者都在認字形，會被同一個模糊字一起騙——
兩個相關的來源等於一個來源。

投票規則：
- 三源一致（差異在容差內）→ `green`，自動採用
- 兩對一 → `yellow`，採多數，`suspect` 記下異議者
- 分歧或有來源回 `None` → `red`，人工輸入

⚠️ **VLM 的失效模式**：傳統 OCR 認錯會給 `36OO` 這種一眼看得出的垃圾；
VLM 會給你乾淨、合理、有自信、而且錯的 `3600`。**對矛盾偵測而言，幻覺遠比誤認致命。**

`04_readings.csv` 欄位：

```
id,sheet_id,kind,value,unit,conf,status,
src_paddle,src_vlm,src_geom,
bbox_x,bbox_y,bbox_w,bbox_h,crop,
verified_value,verified_by,verified_at,note
```

## 5. Orchestrator（中樞迴圈）

```python
# planning/orchestrator.py —— 全系統唯一的流程控制器
MAX_ITER = 3

def run_case(case_dir):
    run_passive(case_dir)                    # s01–s05，任一步已完成可跳過
    prev = None
    for n in range(1, MAX_ITER + 1):
        plan = propose_plan(case_dir, version=n, residuals=prev)   # s06
        problems = validate(case_dir, plan)                  # s06v
        if problems:
            plan = propose_plan(case_dir, version=n, residuals=prev,
                                rejected=problems)                  # 退件重寫，同輪一次為限
            problems = validate(case_dir, plan)
            if problems:
                mark_stuck(case_dir, problems); break
        apply_plan_status(case_dir, plan)      # ★ v0.4.1 新增：把 plan 的裁定回寫
                                               #   03_detections / 03_elements 的 status
                                               #   → adopted/rejected/uncertain
                                               #   獨立一步：s07 只准讀 plan，不能順手回寫
        execute(case_dir, plan)                              # s07
        prev = render_compare(case_dir, plan)                # s08 → residuals_vN.csv
        if residuals_all_handled(plan, prev):                # 程式碼判定，不是 agent 自稱
            break
    export_review(case_dir)                                  # 黃紅＋衝突 → Excel
```

**鐵則**：`for` 迴圈、終止條件、退件，全在這支程式碼；中樞永遠只被呼叫。

## 6. 繪圖計畫 plan_vN.yaml

### 6.1 結構

```yaml
meta:
  case: <案號>_<地段>
  sheet: A-2_一樓平面
  version: 2
  based_on: plan_v1        # v1 填 null
context:                   # 來自 02_sheets，中樞不得自行更改
  kind: plan  floor: 1F  scale: 100  unit: cm  orientation: 0
judgments:
  - id: J001
    type: wall             # 只能用 core/classes.py 的類別
    geometry: { axis_wkt: "LINESTRING(0 0, 806 0)", thickness: 24 }
    evidence: [pair#12, chain#c003]     # ★ 必填，至少一個
    confidence: 0.9
    note: 厚度由線對間距 28px 換算
overrides:                 # 推翻視神經標籤必須留痕
  - label: det#x0101
    action: reject
    reason: 位於圖框排除帶（02_exclude#e02）
conflicts:                 # 對不起來的寫這裡，不准抹平
  - kind: chain_closure
    detail: 二樓X向合計12200，總尺寸12000，差200
    involved: [chain#c007, read#p02_d0038]
uncertain:
  - judgment: J007
    reason: 摺痕帶線證據中斷（quality#q13）
    basis: 依尺寸鏈補全，標低信心
residual_handling:         # v2 起必填：逐條回應上一輪殘差
  - residual: R003
    action: revise         # revise（改判斷）或 report（升級成 conflict）
    detail: J004 厚度 24→15，證據 pair#88
```

### 6.2 驗收規則（`validate`，純程式碼）

退件條件（任一即退）：
1. schema 不合法／類別不在 classes.py
2. 任一 judgment 的 evidence 為空，或引用的 id 不存在於 CSV
3. geometry 座標**無法追溯到** chain 或 measure 來源（禁止目測座標）
4. overrides 缺 reason
5. v2 起：上一輪任何殘差沒有出現在 residual_handling
6. context 被改動

## 7. 中樞的規格

### 7.1 輸入（脈絡節食）

中樞收到的是**摘要**，不是原始資料：
- 02_sheets 該張圖整列、品質地圖摘要（差區清單）、排除帶
- 05_chains 全部（含閉合狀態）
- 03_elements **統計＋高信心清單**（低信心的只給數量，要看自己呼叫工具）
- 上一輪 residuals（v2 起）

### 7.2 主動工具箱（中樞可呼叫）

| 工具 | 輸入 → 輸出 |
|---|---|
| `crop_look(bbox, dpi)` | 區域 → 影像（中樞親眼看） |
| `redetect(bbox, params)` | 區域＋細參數 → 局部線段清單 |
| `read_number(bbox)` | 區域 → 高解析重讀（走三源） |
| `measure(id_a, id_b)` | 兩線/兩點 → 精確像素距離＋換算 cm |
| `trace(line_id)` | 沿線追蹤連通性 → 接合候選（摺痕斷線用） |
| `compare_floors(bbox)` | 同位置多樓層並排影像 |
| `ask_arbiter(read_id)` | → 讀數仲裁 sub-agent |
| `ask_detective(residual_id)` | → 殘差偵探 sub-agent |

### 7.3 System prompt 骨幹（三戒律＋節錄五紀律）

```
你是舊圖重建的中樞。你的產出是一份繪圖計畫，不是動作。
戒律一：不准目測座標。座標只能引用尺寸鏈或 measure 的結果。
戒律二：不准抹平矛盾。對不起來的寫進 conflicts；「帶著矛盾收工」是成功。
戒律三：不准改流程。你在固定骨架內思考，不重排工序。
每個判斷必附證據 id；推翻標籤必附理由；不確定就標 uncertain 並說明補全依據。
標籤是主張不是事實：可以懷疑，但要用工具驗證後才推翻。
```

### 7.4 Sub-agent 規格

- **讀數仲裁**：入＝一張小圖＋三源值＋品質區資訊；出＝`{裁定值|null, 信心, 一句理由}`。可用本地小模型。
- **殘差偵探**：入＝一條殘差＋工具箱（唯讀）；出＝`{建議, 證據, 信心}`。**產出只能進 plan 的 uncertain/judgments 並經驗收，不得直接寫任何 CSV。**
