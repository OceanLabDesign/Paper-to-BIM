# 0006. 技能＝指令包＋選用的可執行腳本

## 脈絡

需求：中樞（planning）要「具備技能（skill）」。

限制：§7.1 脈絡（context）節食（context diet） —— 中樞收到的是摘要不是原始資料，§12 明令
「不要把 649 條線段（line segment）原始資料塞進脈絡」。技能若全部塞進 system prompt，
技能一多就會撐爆脈絡，正好違反同一條紀律。

## 選項

| 選項 | 好處 | 代價 |
|---|---|---|
| 兩者都要（採用） | 指令給中樞讀、程式給中樞呼叫，彈性最大 | 目前只有一個技能，設計面積相對需求偏大 |
| 只做指令包（markdown） | 加技能不用寫程式 | 需要確定性（determinism）計算時無處可放 |
| 只做 Python 模組 | 確定性高、可測試 | 加一個技能就要改程式；判斷性的指導無處可寫 |

## 決定

一個資（personal data）料夾一個技能：`SKILL.md` 必要、`run.py` 選用。
載入器 `planning/skills/__init__.py` 提供 `list_skills()` / `load_skill()` / `run_skill()`，
不引 PyYAML（前置資料（front matter）只讀 `name:` 與 `description:` 兩行），維持零相依。

**按需載入（on-demand loading）**：中樞脈絡平常只放技能名與一行描述，碰到對應情境才載入全文 ——
這是 §7.1 脈絡節食的直接延伸，也是選這個形狀的決定性理由。

## 後果

- 新增技能＝新增一個資料夾，不改程式、不改中樞
- 技能與 sub-agent 同紀律：**唯讀**，產出要經中樞進 plan、經驗收（validation）才算數（§7.4）
- **放棄了「技能一律可測試」** —— `SKILL.md` 那半是給模型讀的判斷指導，測不了
- 重新考慮的時機：若一年後 `SKILL.md` 那半都沒被用到，砍掉只留 Python 模組

## 依據

規格 §7.1、§7.4、§12；2026-08-22 對話裁決（使用者選了「兩者都要」）。
