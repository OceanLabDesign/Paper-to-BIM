# 0011. 補上度量層 —— 拼座標不拼像素，每片求 (dx, dy, px_per_cm)

> **狀態 proposed**。**不取代 ADR 0009**，是把 0009 答應了但沒實作的那一半補上。

## 脈絡

需求原話：「我決定還是前期塞一個拼圖的步驟，我發現你也是要圖全拼好了才能知道全貌」。

### ADR 0009 只做了一半

0009 的決定是「不做像素配準（registration）」，但同一份文件第 99 行也寫著：

> 片內的相對關係由片內的線段與量測決定；**跨片的關係由數字與編號決定**。

後半句從來沒有實作。0009 的後果段還明說：

> **仍然需要的是「排列」，不是「對位」**：要知道哪一張在左上、哪一張在右下
> （拓樸 topology），不需要知道相差幾個 px（度量 metric）。

當時判斷「不需要度量」。下面三筆實測說明那個判斷太早。

### 三筆實測

**1. 沒有共同座標系就分不出「兩個東西是不是同一個」。**
`02_understanding_p03.json` 的四個區塊各自把同一條屋頂邊界取了不同名字。
每個區塊的 `bbox` 是**該區塊內的比例座標**，跨區塊無法直接比較 ——
實體解析（entity resolution）連比對的基準都沒有。0009 把這件事丟給中樞判斷，
但沒給中樞任何可比的座標。

**2. 尺寸鏈的端點是比例座標，跨片就失效。**
2026-08-23 的尺寸 schema 實驗讓判讀者為每筆尺寸給出 `from` / `to` 端點，
成果很好（`190+380+190 = 760` 與圖上獨立標註的總尺寸完全相符）。
但那些端點是**區塊內比例座標**。一條跨越接縫（seam）的尺寸鏈，
兩個端點分屬兩片，沒有共同座標系就加不起來。

**3. `PX_PER_CM` 該每案校，但差距沒有一開始說的那麼大。**
`core/config.py` 寫死 `PX_PER_CM = 1.1811`（68 年案、DPI 300、1:100）。
從 p03 的 23 段尺寸／6 條鏈換算，79 年案實測 **1.207 px/cm，比常數高 2.2%**。

⚠ **這裡先前算錯過一次。** 判讀者回報的「約 1.02 px/cm」是在**縮小後的區塊圖**上量的
（`02_regions/_meta.json` 的 `scale = 0.835`），拿它直接跟整片解析度的常數比，
會得到「差 13%」的錯誤結論。座標空間不同不能直接比 —— 換回整片像素才是 1.207。

2.2% 不足以否定那個常數，但仍值得每案校：806cm 的總寬上是 18cm 的誤差，
而且 68 年案的 DPI／比例尺組合本來就不保證適用其他案。
各段的離散度 17.9%（含判讀者已標明不閉合的鏈），這個數字本身也要往上傳。

而它用的方法正好就是度量層需要的：找一條加得起來的鏈（760 = 190+380+190），
量它的像素跨距（整片 931 px），相除。**尺寸鏈本身就是圖上自帶的尺**。

### 但像素配準仍然不能用

0009 記錄的五次失敗沒有被推翻，共同失敗模式是**理直氣壯地錯**：

| 方法 | 結果 |
|---|---|
| 相位相關 phase correlation | 7 對全錯，誤差 355–920 px |
| ORB ＋ RANSAC | 7 對全錯，41/107 內點 |
| 自寫投影剖面 | 5/7 對，全域求解失敗 |
| `cv2.Stitcher_SCANS` | 回報 status OK，輸出是垃圾 |
| `findTransformECC` | 在**錯答案**上給 cc=1.0000 |

曬圖平面圖上全是等距平行線，點特徵大量誤配而不自知。

## 選項

| 選項 | 好處 | 代價 |
|---|---|---|
| A. 維持 0009 現況（只有拓樸） | 不必新增模組 | 跨片實體解析與跨片尺寸鏈無解；比例尺仍是常數 |
| B. 像素配準求變換矩陣 | 若成功則自動、無須判讀 | 已實測五次失敗，且失敗時不自知 |
| C. **語意錨點求度量**（採用） | 用圖上明寫的東西當錨點，對不上時說得出對不上 | 需要判讀先跑；沒有錨點的接縫只能低信心 |
| D. 合成一張大圖再重新理解 | 「全貌」最直觀 | 需要 B 才做得到；且 4960×3507×4 片縮到模型輸入尺寸會糊掉（0010 已量過） |

## 決定

**採 C。拼座標，不拼像素。**

決定性的理由：**尺寸鏈跨縫閉合這件事，同時給出偏移量與比例尺，而且自帶驗算。**
像素配準沒有驗算 —— 那正是它五次都不自知地錯掉的原因。

產出**不是一張合成大圖**，是每片一組 `(dx, dy, px_per_cm)`，
把片內座標映到該張圖（sheet）的座標系。下游一律用圖座標。

### 證據四階，由強到弱

| 階 | 錨點 | 給出什麼 | 為什麼可信 |
|---|---|---|---|
| 1 | **尺寸鏈跨縫閉合** | 偏移量 ＋ 比例尺 | 數字加得起來就是驗算，加不起來立刻知道 |
| 2 | **圖框（drawing frame）** | 該軸的偏移量 | 印刷直線，位置由紙張決定，不受曬圖劣化影響 |
| 3 | **基準線／軸線延續** | 該軸的偏移量 | 跨縫連續，且圖上通常有編號 |
| 4 | **重疊帶內容重複** | 兩軸偏移量 | 同一個尺寸數字或元件編號在兩片都出現 |

四階都沒有 → 退回 `02_sheets.csv` 已有的網格排列＋標稱重疊，**標低信心**。
**四階彼此打架 → 寫進 `08_conflicts.csv`，不挑一邊**（§1「矛盾是產出，不是障礙」）。

### 這支不定案

沿用 `perception/s01c_register.py` 既有的契約：**只提候選、帶證據、不定案**。
（檔名是 ADR 0008 留下的，機制換掉但檔名保留 —— 改名會動到 §8 的模組表。）

## 後果

- 跨片實體解析有了可比的座標；跨縫尺寸鏈加得起來；比例尺變成每片實測值
- **放棄了「比例尺是全域常數」這件事。** `config.PX_PER_CM` 從此是**後備值**，
  不是真值。由它導出的東西比照 `ASSUMED` 的規矩：信心 ≤ 0.4、輸出帶 `_draft`
- **放棄了「不需要判讀就能排片」。** 四階錨點全部要先判讀過才有 ——
  這一步因此排在理解之後，不是之前。**與 0010「理解優先」同向，不衝突**
- 仍然**放棄合成大圖作為管線的中間產物**（0009 後果第二條不變）。
  有了 transform 之後可以另外算一張縮圖給人看，那是預覽，不是重建的輸入
- 沒有錨點的接縫會是低信心 —— 這是誠實的結果，不是失敗。0009 已預告
  「若該處沒有任何尺寸標註，幾何就只能靠像素接續」，屆時仍照 0009 的規矩：
  **接不起來當成矛盾回報，不硬拼**
- 重新考慮的時機：若某案大量接縫四階全空（例如純設備圖、圖上幾乎沒有尺寸），
  這一步會退化成「只有網格排列」，那時要重新評估像素配準的價值 ——
  但重評的前提是先解決它「錯了不自知」的問題
