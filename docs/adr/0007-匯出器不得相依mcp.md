# 0007. 匯出器不得相依 MCP；確定性不是 byte-identical

## 脈絡

`execution/exporters/` 要支援 AutoCAD、Rhino、VisualARQ、ArchiCAD、Revit。
盤查後發現 ArchiCAD、Revit、Rhino **三家都有現成的 MCP server**，
而本專案本機就有一份 rhinomcp fork（37 支工具），看起來是最省事的管道。

同時 §8 要求 s07「同一份 plan 跑兩次要得到同一份輸出（確定性，
不准有隨機、不准有 LLM）」。

## 選項

| 選項 | 好處 | 代價 |
|---|---|---|
| MCP 只做互動除錯（採用） | 確定性成立；直接打 API 也比較快 | 每條路線要自己寫轉接 |
| 匯出器走 MCP | 現成、少寫程式 | 在確定性管線裡插一個非確定性元件 |

確定性另有一組：byte-identical vs 幾何與屬性等價。

## 決定

**一、MCP 不得成為任何 Exporter 的相依。** MCP 是給模型在不知道 schema 時
臨場探索用的；我們相反 —— schema 已知、固定、可以寫死。
MCP server 只掛開發者的 config 當互動除錯用。
`NEEDS` 刻意不加 `"mcp"` 這個值，免得有人以為那是可選項；
`tests/smoke.py` `[7]` 會 grep 檢查沒有任何 exporter 匯入 MCP。

**二、確定性改為「幾何與屬性等價」，不是 byte-identical。**
照字面讀的話，IFC 每次產生新的 GlobalId、rhino3dm 每次寫新的物件 GUID、
IFC header 還帶時間戳 —— **兩條純檔案路線都一定過不了**。
改為：比對時排除 GUID 與時間戳，且 id 盡量從 judgment id 決定性導出。

## 後果

- 得到一條可執行的確定性定義。原本那句照字面讀會讓 §8 永遠無法通過
- **放棄了 MCP 的省事** —— 但兩條路的產物上限本來就一樣（Rhino 沒有牆型別），
  MCP 那條只是多了「Rhino 要開著、逾時、其實做完了但看起來失敗」的風險
- 旁證：社群裡真要跑批次時會把 MCP 拿掉、直接 POST JSON 到底層 HTTP port
- 重新考慮的時機：若哪天 MCP 有了確定性保證（同輸入必同輸出、無模型參與），
  第一項可以重議；第二項不太可能改回去

## 依據

規格 §8、§12；2026-08-22 的 CAD 落地路線盤查（21 個 agent，逐條查核來源）；
`execution/exporters/base.py`、`tests/smoke.py` [7]。
