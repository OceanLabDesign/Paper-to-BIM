# 0010. 理解優先 —— CV 是破壞性的閘門，不能放在理解之前

> **狀態 proposed**。這是對實作順序的修正，不是對 §7 架構的修改 ——
> 反而是回到 §7.2 主動工具箱的原意。

## 脈絡

實作到目前為止的順序是：

```
影像 → 自適應二值化 ＋ Hough → 1131 條線段 → 中樞 → plan
```

這條路在真材料上連續失敗，而且每加一層 CV 就換一種爛法：

| 失敗 | 實測 |
|---|---|
| 樓梯踏步被當成牆 | 相鄰踏步間距 21–29cm，正好落在 `WALL_GAP_PX` |
| 斜線填充被當成牆 | 配置圖抽出的 9 道「25–34cm 牆」全是填充線 |
| 消防圖抓不到外牆 | 那裡的牆是**單線**，沒有線對可配 |
| 文字偵測漏掉最大的「店舖」、把摺痕框成直排文字 | 幾何規則判斷不了「這是字」 |

### 根因：二值化與 Hough 丟掉了判斷所需的資訊

| 被丟掉的 | 為什麼要緊 |
|---|---|
| **線寬** | 牆是粗線、尺寸線細、基地界線更細 —— 二值化後全變成 1 |
| **線型** | 實線／虛線／一點鏈線，Hough 之後都一樣 |
| **非線內容** | 文字、符號、填充、箭頭、圓弧 —— 全部消失 |
| **整體樣貌** | 「這一坨看起來就是樓梯」需要看整體，不是看線 |

**等中樞拿到匿名線段，資訊已經沒了，再怎麼推理也回不來。**

而牆、樓梯踏步、剖面填充、尺寸線在**幾何上長得一模一樣** —— 都是一組平行線。
差別在語意。CV 分得出「這裡有平行線」，分不出「這組平行線是什麼意思」。

### 這其實是把 §7.2 跑反了

規格 §7.1 說中樞收到的是**摘要**；§7.2 給了 `crop_look` 等工具，
用意就是**讓中樞自己去看圖**。把批次抽取的結果當成中樞理解的來源，
等於用摘要取代了看圖 —— 而摘要是有損的。

## 選項

| 選項 | 代價 |
|---|---|
| A. CV 先行（現況） | 已連續失敗；資訊在中樞看到之前就被丟掉 |
| B. **理解優先**（採用） | 中樞看的是影像，token 成本較高；需要分塊以保留細節 |
| C. 用更好的 CV | 換再多演算法也解不了「平行線群是什麼意思」這個語意問題 |

## 決定

**採 B。順序改成：**

```
影像 ──► 中樞看圖（高解析分塊，不二值化）
           │
           ├─► 語意元素 ＋ 粗略區域（「這是樓梯」「這塊是填充」「牆大致在這」）
           │
           ▼
        CV 只量中樞指名的東西 ──► 精確座標／厚度／長度
           │
           ▼
        judgment（引用量測結果與線段 id 當證據）
```

**分工**：中樞判斷「是什麼」（它擅長、CV 做不到）；CV 量「在哪、多長」
（它精準、且不需要學習）。沒有人做自己不擅長的事。

### 批次抽取的角色改變

`s03_lines` 等仍然要跑，但**不是給中樞理解用的**，而是作為
**可引用的證據庫** —— §6.2 規則 2 要求 evidence 的 id 必須存在於 CSV，
所以中樞說「這裡有一道牆」時，要指得出是哪幾條線段支撐這個判斷。

理解來自看圖；證據來自 CSV；座標來自量測。三者分開。

### 分塊是必要的

整頁 4960px 縮到多模態模型的輸入尺寸是 0.32×，12cm 內牆的 14px 會變成 4.4px
（兩條線糊成一條）。切成 3×2 重疊分塊後是 0.83×，**保住 2.6 倍細節**。

## 後果

- 中樞的 token 成本上升（要看六張圖而不是讀一份摘要）——
  但 §7.1 脈絡節食的原意是「不要塞原始線段資料」，不是「不要看圖」
- **放棄了「一次批次跑完就有答案」的期待。** 理解是要花成本的
- 座標仍然只來自量測（§6.2 規則 3 不變）；中樞指的是**區域**，不是座標
- 重新考慮的時機：若某類元素 CV 的判準足夠可靠（例如尺寸鏈上的數字位置），
  那一類可以走批次，不必每次都問中樞

## 依據

規格 §7.1、§7.2、§6.2 規則 2 與 3；2026-08-22 在
`cases/79-B37001_七賢二路` 上的連續失敗量測；使用者的指正
「CV 會把資訊清除，變成抽象的線條，所以理解應該放在第一步」。
