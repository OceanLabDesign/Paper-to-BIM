# 0009. 理解而非拼圖 —— 不做像素對位，靠語意連結重建全案圖資

> **狀態 proposed**。取代 ADR 0008 的問題框架（0008 問「怎麼拼」，本文問「要不要拼」）。

## 脈絡

需求原話：「工具的功能在於**理解**而不是拼圖，不用實際拼圖就可以做全案圖資的
mapping 進而重繪」。

### 拼圖這條路實測撞了四次牆

在合成測資（真值已知）上量過：

| 方法 | 結果 |
|---|---|
| 相位相關 phase correlation | 7 對全錯，誤差 355–920 px |
| ORB ＋ RANSAC | 7 對全錯，且給出 41/107 內點這種**看起來很有信心的錯答案** |
| 自寫投影剖面＋墨水一致度 | 5/7 對，全域求解失敗 |
| `cv2.Stitcher_SCANS` | **回報 status OK，輸出是六片隨機角度散開的垃圾** |

共同失敗模式：**理直氣壯地錯**。曬圖平面圖上全是等距平行線，
點特徵大量誤配而不自知。

### 真實檔案給了決定性的證據

`cases/79-B37001_七賢二路` 的 44 頁掃描（民國 79 年高雄市，大裕建設及公大樓新建）：

1. **每頁正好一張完整 A3 掃描**（3507×4960 px＝A3 300dpi），放在 (0,0)，
   整批旋轉 90°。**PDF 裡沒有任何偏移量可讀** —— §8 那條捷徑不適用
2. **標題欄每 4 頁出現一次**（p1, p5, p9, p13, …, p41）
   → 44 頁＝**11 張大圖，每張掃成 4 張 A3**
3. 圖名讀得出來：地下室一樓／一樓／二樓／三樓／四～十樓火警警報消防設備平面圖、
   十一樓／十二樓自動撒水消防設備平面圖…

### 為什麼是四張：影印機的物理限制

原圖是 **A1 或 A2**，事務所的影印機**最多只能印 A3**，所以一張完整的圖被拆成數張 A3。
本案是一張拆四張（A1 = 2×2 的 A3，尺寸剛好）。

**這是真的空間切分，不是「四個不同性質的區域」。** 之所以每張內容看起來性質不同
（一張多是平面、一張多是說明文字、一張多是設備表），是因為**原本那張 A1 上就是
這樣配置的** —— 切成四塊之後，每塊自然落在不同的內容區。兩件事不衝突。

### 但排列順序可以純靠理解推出來（已實測）

以第 1 張圖（p1–p4）為例：
  - `p1` 底部是標題欄的**右半**（事務所名／工程名稱／圖名／圖號）
  - `p4` 底部是**左半**（核准／繪圖／設計／比例尺欄位），
    且「祥慶源」三字出現在 `p4` 的**最右緣** —— 正是 `p1` 左緣的起點
  - ⇒ p4 緊鄰 p1 左側，兩張都是下排；p3、p2 為上排

```
p3 左上   p2 右上
p4 左下   p1 右下   ← 標題欄橫跨這兩張的底緣
```

**PDF 的頁序不等於空間順序**（本例是 1=右下、2=右上、3=左上、4=左下）。
而這個排列是從**標題欄被切斷的位置**與內容連續性讀出來的，
**沒有用到任何像素對位**。

## 選項

| 選項 | 做法 | 代價 |
|---|---|---|
| A. 像素對位（ADR 0008 的框架） | 求出每片的變換矩陣，合成整頁 | 已實測四次失敗；而且拼好了也還是要理解 |
| B. **語意連結**（本文採用） | 逐片理解內容，靠圖上明寫的識別資訊跨片連結 | 需要可靠的判讀；連不起來時要能明說 |

## 決定

**採 B。不做像素對位。**

連結的依據**寫在圖上**，不需要幾何：

| 依據 | 連結什麼 |
|---|---|
| 標題欄的圖號、圖名、樓層 | 哪些片屬於同一張圖；哪張圖是哪一層 |
| 尺寸鏈上的**數字** | 長度。§1：「尺寸是幾何、線段只是拓樸」—— 長度來自數字，不來自像素 |
| 元件編號（W1／D2／C1） | 平面上的開口 ↔ 門窗表上的規格。門窗表**在另一張圖上** |
| 室名、樓層標記 | 同一空間在不同圖上的對應 |
| 接圖線／「接續於第 X 張」 | 製圖慣例本來就標了 |

這些正是 `core/classes.py` 裡 `element_tag`、`room_label`、`dim_text`、
`level_text` 這幾類存在的理由 —— **它們是連結鍵，不只是待偵測的圖形**。

### 為什麼不需要像素對位就能重繪

§1 第三條：「尺寸是幾何、線段只是拓樸；座標只來自數字與量測。」

長度既然來自尺寸鏈上的數字，**片與片對不對得齊就不影響幾何**。
片內的相對關係由片內的線段與量測決定；跨片的關係由數字與編號決定。

## 後果

- 不需要拼接函式庫，不需要 GPU，不需要學習式特徵匹配的模型權重授權
- **放棄了「合成一張完整大圖」這個中間產物**。使用者若想看整張圖，
  那是另一個需求（給人看的預覽），不是重建的必要條件
- 連結失敗時的行為與其他矛盾一致：進 `conflicts`／`uncertain`，傳給人，
  不硬猜。這比拼歪一張看起來完整的圖安全得多
- 需要補的東西：`02_sheets.csv` 要能表達「多片屬於同一張圖」與片的角色
  （平面／說明／表格／簽核）；跨片的實體解析要成為中樞的判斷
- **仍然需要的是「排列」，不是「對位」**：要知道哪一張在左上、哪一張在右下
  （拓樸），不需要知道相差幾個 px（度量）。排列由標題欄位置、內容連續性、
  尺寸鏈與軸線的接續推得
- 重新考慮的時機：若某張平面圖跨片而該處**沒有任何尺寸標註**，
  幾何就只能靠像素接續 —— 那時對位的價值才會回升。
  但即使那時，尺寸鏈仍然優先於像素，而且「接不起來」要當成矛盾回報，不是硬拼
