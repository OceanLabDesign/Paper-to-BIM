# 0008. 輸入是拼版 PDF 還是單張掃描影像

> **狀態 proposed** —— 已寫但尚未拍板。等負責人裁決後改 accepted。

## 脈絡

產品的使用情境是「事務所從檔案室調出建築執照圖，掃描後上傳」。
但規格假設的輸入不只是 PDF，是**特定一種 PDF**：

- §3：`00_raw/  原始 PDF（唯讀）`
- §8 `s01_ingest`：「用 PyMuPDF 讀每個影像 XObject 的放置矩陣 ——
  **Illustrator 拼的檔案偏移量就在裡面，不用重新對位**」
- §8 同時明文禁止：「不要做特徵點拼接」

整條「免拼接」的省事之處，來自**偏移量已經被前一個人存進 PDF 裡**。
使用者若上傳 JPG／PNG，那個矩陣不存在，捷徑就沒了。

而事務所從檔案室調出來的圖，實務上多半是一張一張掃的，
不見得經過拼版軟體。

## 選項

| 情況 | 好處 | 代價 |
|---|---|---|
| A. 只吃拼版 PDF（現況） | 免拼接，偏移量精確，下游座標可信 | 要求使用者先拼好，可能不符實務 |
| B. 加一條單張影像路徑（建議） | 成本低；單張圖沒有拼接問題 | `s01_ingest` 要依副檔名分流 |
| C. 支援多張影像自動拼接 | 使用者什麼都不用做 | **直接撞 §8 的禁令**；拼歪了下游全錯，而且錯得不明顯 |

## 決定

**待裁決。** 傾向 A ＋ B，暫不做 C。

B 的成本很低：單張影像就是一列 offsets、`x=y=0`、旋轉交給 s01b，
`01_offsets.csv` 的欄位一個都不用改。

C 被 §8 禁掉是有道理的 —— 特徵點拼接失敗時的失敗模式很差：
圖看起來是完整的，只是尺寸全錯，而且要量過才知道。
若事務所的實際材料就是「A3 掃描器分三次掃一張 A1」，這條遲早要面對；
折衷是不自動拼，但提供「請先拼好」的檢核與提示。

## 後果

- 採 A＋B：對外可以誠實說「支援 PDF 與單張影像」，多張影像要先自行拼版
- **放棄了「使用者什麼都不用管」的體驗** —— 這是刻意的：
  拼接錯誤會污染整條下游，而下游的所有信心標記都會因此失去意義
- 重新考慮的時機：累積夠多「使用者手上只有多張分次掃描」的真實案例時

## 依據

規格 §3、§8；2026-08-22 對使用情境的說明；`perception/s01_ingest.py` 的輸入契約。
