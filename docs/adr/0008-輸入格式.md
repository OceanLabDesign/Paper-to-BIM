# 0008. 散開的掃描影像如何進入座標系

> **狀態 superseded**，由 [ADR 0009](0009-理解而非拼圖.md) 取代。
> 本文問的是「散開的片怎麼對位」；0009 問的是「要不要對位」，答案是不用。
> 內容保留不改 —— 它記錄了當時的判斷與四次失敗的量測。

## 脈絡

使用情境是「事務所從檔案室調出建築執照圖，掃描後上傳」。
實務上多半**一張一張掃**，不見得經過拼版軟體。

而 `s01_ingest` 目前只吃一種輸入：**經過拼版的 PDF**。它的省事之處來自
規格 §8 —— 「Illustrator 拼的檔案偏移量就在裡面，**不用重新對位**」。
JPG／PNG 沒有那個放置矩陣，這條捷徑不存在。

### 關鍵在於規格 §1，不在 §8

規格 §1 第三條：「**尺寸是幾何、線段只是拓樸；座標只來自數字與量測。**」

這條把問題切成兩半，而且切法對我們有利：

- **拓樸**（哪道牆接哪道、開口開在哪面牆上）—— 視覺與中樞判讀得出來，
  **不需要精確對位**
- **幾何**（這道牆 806 cm）—— 來自**尺寸鏈上的數字**，也不需要精確對位

換句話說：**拼得準不準，多數情況下不決定幾何。**

### 第一版錯在哪

第一版寫「§8 明文禁止特徵點拼接」，並據此排除自動拼接。
**規格沒有這句話。** 那是 `perception/s01_ingest.py` 的 docstring 自己加的，
被當成規格引用（已修正）。規格說的是「不用」重新對位，不是「不准」。

## 選項

| 選項 | 做法 | 代價 |
|---|---|---|
| A. 只吃拼版 PDF（現況） | 偏移量從 PDF 讀 | 要求使用者先拼好，不符實務 |
| B. 加單張影像路徑 | 整張當一個 tile，offsets 全 0 | 幾乎零成本，但只解決單張的情況 |
| C. 前處理階段做特徵點拼接 | 傳統 CV 對位後再進 s03 | 失敗模式很差：**圖看起來完整、只是尺寸全錯，且要量過才知道**；而且它是 s03 之前的盲步驟，錯了沒有人發現 |
| D. **對位當成中樞的判斷**（建議） | perception 不強求全域座標系；中樞用視覺＋尺寸鏈提出片間關係，**當成一筆帶證據的 judgment** | 中樞脈絡要多帶片間關係；validate 要多一條規則 |

## 決定

**待裁決，傾向 A ＋ B ＋ D。**

D 是這次討論真正的產出。它跟 C 的差別不是技術，是**位置**：

- C 把對位放在**視神經層**——盲的、確定性的、錯了不會有人知道
- D 把對位放在**中樞層**——它是一筆判斷，要附證據，要過驗收，
  對不起來時會落進 `uncertain` 或 `conflicts`

而這正是整個系統原本就在做的事。對位失敗在 D 之下不是災難，是**產出** ——
「這兩片接不起來」會跟其他矛盾一樣傳到人面前，不會被無聲抹平。

中樞手上已經有做這件事的工具：`crop_look` 親眼看接縫、`trace` 追斷線、
`measure` 量片內距離、加上尺寸鏈的數字當基準。

## 後果

- 對外可以說：支援拼版 PDF 與單張影像；多張分次掃描時，
  **片間關係由中樞判定並附證據**，判不出來就標記，不會硬拼
- **放棄了「盲拼接」的省事**。也放棄了「拼不起來就拒絕處理」的保守做法
- 需要補的東西：`perception` 的輸出要容許「多個未對位的片」；
  中樞脈絡要帶片間關係；`validate` 要能檢查對位判斷的證據；
  `s08` 對照要能在未對位時退化成逐片比對
- 重新考慮的時機：若實測發現尺寸鏈的覆蓋率太低（大量牆沒有標註尺寸），
  幾何就會大量依賴 `measure`，那時精確對位的價值會回升

## 依據

規格 §1 第三條、§8 `s01_ingest`（原文為「不用重新對位」）、§7.2 中樞工具箱、
§6.2 規則 3（座標只能追溯到 chain 或 measure）；2026-08-22 對話中對
「既然已經有視覺，搭配 agent，散開的圖應該也能被理解」的質疑。
