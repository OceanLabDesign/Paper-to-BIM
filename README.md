# Paper-to-BIM

**把民國 68 年（1979）的建照曬圖，重建成可用的 BIM 模型。**

> **現況：骨架階段。** 流程骨架與契約已定，模組多數仍是 stub，
> 契約三件套是待審核的草案，尚未跑過任何真實案件。
> 詳細進度見下方[建造順序](#建造順序)。

---

## 問題

一張 1979 年的建照圖，掃描進來是這樣：曬圖底色不均、對折處有摺痕白帶、
針筆線 0.4–0.6 mm 在 300 dpi 下只有 5–7 px、曬圖擴散後兩條平行線會糊成一條粗帶。

人看得懂。程式看不懂。

而且它不只是「認不出來」那麼單純 —— 更麻煩的是**認錯了卻看起來很合理**：

- 尺寸標註寫著 `403`，OCR 可能讀成 `4O3`，也可能讀成乾淨、合理、而且錯的 `408`
- 一道 12 cm 的內牆，兩條線只隔 14 px，糊在一起就變成一條線 —— 整面內牆消失
- 二樓 X 向的尺寸鏈加總 12200，但總尺寸標的是 12000

**最後那一項才是重點。** 差的那 200 是圖上真的有矛盾，還是我們讀錯了？
自動化系統遇到這種事，最常見的作法是挑一邊、把差額均攤掉，然後產出一個
看起來很完整的模型 —— 而那個模型是錯的，且沒人知道錯在哪。

## 怎麼做

### 控制權在程式碼，不在 agent

迴圈次數、終止條件、退件重寫，全部寫死在 `planning/orchestrator.py` 的
`for` 迴圈裡。中樞（LLM）只被呼叫 —— **它不能決定要不要再跑一輪**。

### 腦手分離

中樞的產出是一份**繪圖計畫**（YAML），不是動作。
執行那一層只讀計畫、不讀原始偵測資料。中樞說不清楚的東西，畫不出來。

### 矛盾是產出，不是障礙

對不起來的東西寫進 `08_conflicts.csv`，**不准挑一邊蓋掉另一邊**：

```yaml
conflicts:
  - kind: chain_closure
    detail: 二樓X向合計12200，總尺寸12000，差200
    involved: [chain#c007, read#p02_d0038]
```

**帶著矛盾收工是成功。** 那 200 的差額會一路傳到人的面前。

### 不確定往上傳，不往下傳

讀數走三個**機制上獨立**的來源：OCR 字形比對、視覺語言模型的語意理解、
以及完全不看文字、只算端點距離乘比例尺的幾何推算。

第三源是關鍵 —— 前兩者都在認字形，會被同一個模糊的字**一起騙**。
兩個相關的來源等於一個來源。

三源一致才自動採用；兩對一標黃；分歧標紅送人工。
值未定就是未定，不准往下游傳。

> 代價很明確：這套系統**不追求全自動**。它追求的是「哪裡不確定，你一眼看得到」。

## 產出

中樞不畫圖，它寫計畫。每一筆判斷都必須附證據 id，否則驗收會退件：

```yaml
judgments:
  - id: J001
    type: wall
    geometry: { axis_wkt: "LINESTRING(0 0, 806 0)", thickness: 24 }
    evidence: [pair#12, chain#c003]      # 必填，至少一個
    confidence: 0.9
    note: 厚度由線對間距 28px 換算

uncertain:
  - judgment: J007
    reason: 摺痕帶線證據中斷（quality#q13）
    basis: 依尺寸鏈補全，標低信心
```

驗收是**純程式碼**的閘門，六條規則任一不過就退件重寫。其中兩條最要緊：
**證據 id 必須真的存在於 CSV**（不是查格式，是實際去查）、
**座標必須追溯得到尺寸鏈或量測結果**（禁止目測座標）。

## 架構

```
掃描 PDF
  ↓  perception ── 視神經，確定性，一次跑完，不迴圈
     拆片 → 轉正 → 版面 → 品質地圖 → 線段 → 偵測 → 文字 → 富標籤 → 三源讀取 → 尺寸鏈
  ↓
┌─ planning ── 迴圈，控制權在 orchestrator，最多 3 輪 ──────────────┐
│   中樞（LLM）           → plans/plan_vN.yaml                      │
│   驗收（純程式碼）       → 沒引證據就退件，同輪重寫一次為限          │
│   execution            → 照計畫確定性執行，出 DXF                  │
│   對照（像素重疊算術）   → residuals_vN.csv ──回饋──→ 中樞          │
└────────── 終止＝「殘差皆已修或已報告」，由程式碼判定 ────────────────┘
  ↓
跨樓層檢查 → Excel 校對 → 人
```

| 套件 | 角色 | 內容 |
|---|---|---|
| `core/` | 契約 | CSV 欄位、15 類偵測類別、計畫結構、實測校準參數 |
| `perception/` | 看 | s01–s05，確定性，不諮詢 LLM |
| `planning/` | 判斷 | orchestrator、中樞、驗收、工具箱、技能、LLM 供應商層 |
| `execution/` | 畫 | DXF / IFC / ArchiCAD / Revit / Rhino / VisualARQ 匯出器 |
| `review/` | 校對 | 跨樓層檢查、Excel 匯出 |

中樞不是只能被動接收摘要 —— 它有一組**唯讀**的主動工具：切圖親眼看、
用不同參數重跑局部偵測、高解析重讀數字、量兩個東西之間的精確距離、
沿線追蹤摺痕造成的斷線、把同位置的各樓層並排比對。

## 校準

參數是**實測**出來的，不是調出來的。以 1:100、300 dpi 為例：

```
1 cm ≈ 1.181 px       24 cm 牆 ≈ 28 px       806 cm 總寬 ≈ 952 px
自適應二值化 (31, 12)  ← 禁用 Otsu，這組才在曬圖陰影下活得下來
```

`tests/smoke.py` 每次都會重新驗算這些數字 —— 有人「順手優化」就會紅。

## 建造順序

刻意讓**假中樞先於真中樞**：迴圈、驗收、執行、對照全部先用回固定計畫的假中樞驗通，
真的接上 LLM 時只剩一個變因。

| 步 | 做什麼 | 閘門 | |
|---|---|---|---|
| 1 | 契約三件套 | — | 🟡 草案待審 |
| 2 | 拆片與偏移量 | offsets 對得上原拼版 | ⬜ |
| 3 | 轉正、品質地圖、線段偵測 | 疊圖目視：牆心線壓真牆 | ⬜ |
| 4 | 三源讀取與尺寸鏈閉合 | 十張圖實驗 ≥ 目標正確率 | ⬜ |
| 5 | orchestrator ＋**假中樞**跑通全迴圈 | DXF 在 ArchiCAD 打得開 | ⬜ |
| 6 | 接真中樞 ＋ 兩個 sub-agent | 68 年案全頁六圖跑完 | ⬜ |
| 7 | 挑**最爛的一件案**重跑 | 爛圖也活著，才算數 | ⬜ |
| 8 | IFC 匯出 | ArchiCAD 四道牆往返測試通過 | ⬜ |

## 開始

```bash
python3 tests/smoke.py     # 骨架健檢：模組、契約、測資、逐字區塊
```

**現在什麼都不用裝** —— 骨架健檢只要 **Python 3.10–3.14**
（上下限來自 IfcOpenShell 與 rhino3dm 的支援範圍）。

其餘相依照建造順序分階段裝，不要一次全裝：

| 步 | 需要 |
|---|---|
| 2–3 | `pip3 install pymupdf opencv-python numpy` |
| 3 | PaddleOCR-VL（很重，帶 PaddlePaddle，可延後到真的要跑文字時） |
| 5 | `pip3 install ezdxf openpyxl` |
| 6 | 中樞：雲端設 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`，或本地跑 Ollama / vLLM / LM Studio |
| 8 | `pip3 install ifcopenshell` |

先查現況再裝：

```bash
python3 -c "
for m in ['yaml','fitz','cv2','numpy','ezdxf','ifcopenshell','rhino3dm','openpyxl']:
    try: __import__(m); print('  ✓', m)
    except ImportError: print('  ✗', m)"
```

**本地模型不只是省錢**：掃描圖含個資與著作權，跑本地模型時圖不出機器。

### 外部 CAD 軟體：一律不是必要的

DXF 與 IFC 都是**純檔案輸出**，不需要安裝任何 CAD。
以下只在你要「該軟體裡可編輯的原生牆」時才需要，而且**全部不需要 API token**：

| 目標 | 需要 |
|---|---|
| 驗 IFC | Blender 4.2+ 與 Bonsai（免費，建議先用它驗） |
| ArchiCAD | ArchiCAD 25–29 執行中 ＋ 授權 ＋ Tapir Add-On ≥ 1.5.7 |
| Revit | **Windows** ＋ Revit 完整版（LT 沒有 API）＋ pyRevit ≥ 6.5.4 |
| VisualARQ | **Windows** ＋ Rhino 8 ＋ VisualARQ 3 商業授權 |

## 不做的事

同樣重要的是刻意**不做**什麼：

- ❌ 把迴圈控制交給 agent（含「讓中樞自己決定要不要再跑一輪」）
- ❌ 中樞直接寫 CSV 或直接呼叫繪圖函式庫 —— 它只准產計畫
- ❌ 把數百條線段的原始資料塞進中樞脈絡 —— 給摘要，細節靠工具
- ❌ 為了收斂挑一邊蓋掉另一邊 —— 殘差處理只有「改判斷」或「升級成矛盾」
- ❌ 一開始就上資料庫、做網頁校對介面、追求全自動
